## 二、标签与输入窗口：核心逻辑是正确的

### 2.1 当前预测的究竟是什么？

你的代码定义：

```python
target[t] = close[t] / close[t-1] - 1
```

随后构造：

```python
X = features[first:end + 1]
y = target[end + 1]
```

因此，每个样本实际上是：

\[
X_t=[F_{t-L+1},\ldots,F_t]
\]

\[
y_{t+1}=\frac{C^{hfq}_{t+1}}{C^{hfq}_t}-1
\]

预测时刻是：

\[
D_t=\text{下一交易日 }t+1\text{ 的北京时间 08:30}
\]

**这符合你描述的目标，没有发现多移一天或少移一天的问题。**

### 2.2 最后一列放 `stock_return`，不是泄露

这里要明确区分：

- 输入中的 `stock_return[t]`：已经发生的收益率；
- `samples.csv` 中的 `y_raw`：下一交易日收益率。

你的窗口没有包含 `target_pos` 那一行，所以输入里只有历史收益率，没有直接放入待预测收益率。

而且 TimeXer 的 `MS` 分支正是把最后一列作为内生目标序列，其余列作为外生变量：[1]

```python
en_embed = ... x_enc[:, :, -1]
ex_embed = ... x_enc[:, :, :-1]
```

**因此，你把 `TARGET` 固定放在最后一列，与 TimeXer 的设计一致。**

不要误把最后一列历史收益率删掉；需要禁止的是把样本级 `y_raw` / `y_scaled` 拼到输入里。

### 2.3 全量保存未来行，不等于模型看到了未来

`feature_matrix.npy` 包含训练、验证、测试全区间，本身不是泄露。

决定是否泄露的是：

1. Dataset 是否严格按索引切窗口；
2. 预处理参数是否只来自训练区间；
3. 特征值是否在预测时刻已经可获得。

你前两项基本做对了，第三项还有问题，后面展开。

## 三、与 Time-Series-Library 的接口：目前不能直接用原训练入口跑

### 3.1 Dataset 返回值不匹配

你返回的是：

```python
return x, y
```

原项目的训练、验证和测试循环都要求：[2]

```python
batch_x, batch_y, batch_x_mark, batch_y_mark
```

因此，即使把 Dataset 加进项目，也会遇到二元组与四元组解包不匹配。

此外：

- 数据工厂目前没有注册你的 Dataset；
- 数据工厂传入的是 `args/root_path/data_path/flag/size/...`；
- 你的构造函数只接受 `root, split`。[3]

**不能只在 `data_dict` 加一行就完成接入。**

### 3.2 原测试逻辑还依赖额外接口

原项目测试函数会访问：

```python
test_data.scale
test_data.inverse_transform(...)
```

你的类没有这些接口，只有：

```python
inverse_target(...)
```

而且原测试代码可能对：

- `[N, 1]` 的预测目标；
- `[N, F]` 的输入特征；

调用同一个 `inverse_transform`。[2]

你的不同特征有不同标准化参数，不能把 `inverse_target` 直接重命名后同时用于两者。

### 3.3 建议优先采用独立训练循环

对目前这个定制任务，最清楚的方式是：

> 保留项目的 TimeXer 模型，自己写股票任务的训练、验证、测试循环。

核心调用就是：

```python
pred = model(batch_x, None, None, None)
assert pred.shape == batch_y.shape
loss = criterion(pred, batch_y)
```

TimeXer 当前实现不使用 decoder 输入进行预测，因此这种调用适用。[1]

建议配置：

```python
task_name = "long_term_forecast"
features = "MS"
seq_len = preprocessing["config"]["seq_len"]
pred_len = 1
enc_in = len(preprocessing["feature_columns"])
c_out = 1
label_len = 0
```

这里：

- **`features="MS"` 是关键**；
- `c_out=1` 不能代替 `MS`，因为 TimeXer 的分支选择和内生变量数量主要由 `features` 决定；
- `long_term_forecast` 是复用这条预测训练路径，不表示必须预测很多天。[1][5]

如果坚持适配原训练循环，必须同时处理数据工厂、四元组接口、反标准化和评估逻辑。

还有一个隐藏问题：你的 `batch_y` 只有未来标签，没有历史 decoder 上下文。如果保留默认 `label_len=48`，原训练循环会把这个未来标签拼入 `dec_inp`。**当前 TimeXer 忽略它，所以不会因此影响预测；但换成使用 decoder 的模型后就可能造成直接泄露。**因此应设置 `label_len=0` 或彻底去掉这段逻辑。[1][2][5]

### 3.4 不建议转成 CSV 后直接交给 `Dataset_Custom`

它会按约 70%/10%/20% 重新切分，并自行拟合标准化，不会使用你的 `samples.csv` 和指定日期边界。[4]

更重要的是，你导出的矩阵中，无效核心行可能已经被中位数填补；只有 `samples.csv` 在阻止这些行进入有效窗口。改用通用 Dataset 后，这层保护也可能丢失。

## 四、一个容易忽略的严重问题：默认 patch 会遗漏最近的目标历史

你的默认配置：

```python
seq_len = 60
```

项目默认：

```python
patch_len = 16
```

TimeXer 使用不重叠、无补齐的 patch：[1][5]

```python
x.unfold(dimension=-1, size=patch_len, step=patch_len)
```

长度 60，patch 长度 16，只会形成：

```text
0～15
16～31
32～47
```

**第 48～59 行，也就是最近 12 个交易日的历史目标值，不会进入内生 patch 分支。**

注意，这不是所有最近特征都被丢弃：

- 其他外生特征仍通过外生嵌入看到完整窗口；
- `use_norm=1` 时，窗口均值和方差仍会使用全部目标历史；
- 但最近 12 天历史收益率的详细时序信息没有进入目标 patch。

对于下一日收益率预测，这是很不理想的默认行为。

建议：

```python
assert 1 <= patch_len <= seq_len
assert seq_len % patch_len == 0
```

例如：

```text
seq_len=60，patch_len=5 / 10 / 12
seq_len=64，patch_len=16
```

具体选哪个由验证集决定，但应先消除无意的尾部截断。

## 五、数据泄露审查：代码是“按假设因果对齐”，不是“已证明无泄露”

### 5.1 已经做对的部分

以下设计值得保留：

- 不使用 `bfill`；
- `merge_asof(direction="backward")`；
- 滚动指标只使用当期和过去数据；
- 特征筛选只看训练输入行；
- 中位数、均值和标准差只在训练输入行拟合；
- 标签使用与历史目标列相同的标准化参数；
- 推理复用训练列顺序和标准化参数；
- 不跨缺失行情直接计算相邻有效记录收益率。

尤其是：

```python
fit_mask[row.start_pos:row.end_pos + 1] = True
```

它只取训练样本实际用到的输入行，并且按行去重，避免把重叠窗口重复计入统计量。这个做法合理。

### 5.2 最大风险：`available` 是你推算的，不是真实发布时间

目前：

```python
available = observed_date + lag_days + release_hour
```

然后断言：

```python
available <= decision_time
```

这个断言只能证明：

> 数据满足你配置的滞后假设。

不能证明：

> 历史上的那个时间点，这个值真的已经发布并可获取。

例如某个估值指标记录为 3 月 1 日，但实际值是后续财报发布后回算的：

```text
业务日期：3 月 1 日
脚本假设可用：3 月 3 日
实际该版本可用：4 月 30 日
```

即使做了两天滞后，也仍然存在事后信息风险。

### 5.3 “统一延迟两天”不能解决所有来源

需要分别核验：

| 来源 | 核验重点 |
|---|---|
| 百度 | 日期含义、实际更新时刻、历史补录和修订 |
| 估值 | PE 类型、财务分母版本、是否按最新财报重算历史 |
| 两融 | 发布时刻、字段单位、缺失含义 |
| TradingView | 日线日期归属、交易所时区、夏令时、是否含未收盘日线 |
| 后复权行情 | 复权算法、历史更新方式、公司行动处理 |

此外，`lag_days` 使用的是**自然日**，不是交易日。星期五加两天得到星期日。这不一定错误，但必须与数据源发布规则一致。

尤其要防止把某个日线来源改成：

```json
{"lag_days": 0, "release_hour": 0}
```

因为脚本会读取到 `next_session` 的数据。若离线库里有目标日完整日线，代码就可能把它视为目标日凌晨已经可用，从而在 08:30 使用目标日收盘后的信息。

### 5.4 正确方向：保存数据版本及其可用时刻

建议原始表至少增加：

```text
observed_at       数据对应的业务时刻或期间
published_at      来源发布时间
first_seen_at     系统首次获取该版本的时间
ingested_at       入库时间
revision_id       修订版本
value
```

历史回放时，选择预测截止时刻之前已发布、且按你的实际部署约束可取得的版本。

如果没有历史版本库，就应明确标注：

> 当前回测采用最新历史数据和假设发布时间，不能证明严格 point-in-time 无泄露。

**这不是说当前数据一定泄露，而是现有证据不足以排除泄露。**

## 六、“不追溯更新历史快照”的承诺，目前代码并未完全实现

这是你脚本中需要重点修改的一处。

你的说明写着：

> 不会在后来的预测时点追溯更新过去各行的辅助数据快照。

但实际 `infer` 会：

1. 重新读取数据库中的历史数据；
2. 重新计算历史辅助特征；
3. 重新生成完整历史矩阵；
4. 只冻结预处理参数。

因此，如果数据库中的旧值发生了修订：

```text
训练时：某历史行百度值 = 100
推理时：同一历史行百度值 = 130
```

那么新生成的历史特征行仍会改变。

**冻结列名和 scaler，不等于冻结历史数据快照。**

严格来说，你现在保证的是：

> 每次构建时，历史行都按自己的截止时间匹配数据日期。

但尚未保证：

> 每个历史行始终使用当时实际可获取的数据版本。

建议二选一：

1. 使用带版本的数据源，按真实可用时间回放；
2. 每个预测日将已经构造好的特征行持久化，后续只追加新行，不覆盖历史行。

第二种能保证系统上线后的可复现性，但不能补救过去历史数据缺少版本的问题。

## 七、交易日历：当前算法可能把缺数据错误地变成休市

你的历史日历是：

```python
calibrated = derived.intersection(actual)
```

其中 `actual` 要求当日至少有 50 只股票有后复权行情。

这可以剔除某些错误标为交易日的休市日，但反过来：

> 一个真实交易日，如果因为采集故障不足 50 只股票，也会被当成休市日删除。

后果分两种：

1. **目标股票当天有行情**：后续 `unknown` 检查可能直接报错；
2. **目标股票当天也缺行情**：当天从日历消失，前后两天变相邻，你可能把跨两个交易日的收益率当成单日收益率。

第二种是严重的标签口径错误。

此外，`intersection` 只能删日，不能恢复被 `holiday_calendar` 错误排除的真实交易日。

建议调整原则：

> 交易日历决定某天应不应该交易；行情覆盖率决定某天数据完整不完整。两者不能混为一谈。

建议使用权威交易日历；发现低覆盖日时：

- 保留交易日；
- 标记数据异常；
- 补采或阻止导出；
- 不要静默删除日期。

`is_holiday_related` 是否严格表示证券市场休市，也需要查看表的生成代码，不能只根据字段名称确认。

## 八、停牌和无效样本：保守，但会改变你的预测对象

你要求：

```python
整个输入窗口 core_valid
目标日期 core_valid
```

### 8.1 优点

它避免了：

- 把停牌缺行情填成正常收益率；
- 把多日收益率误当单日收益率；
- 在缺失目标上训练。

### 8.2 代价

单个缺失行情日，可能导致后续约一个窗口长度的样本都无法使用；因为缺失日后的第一天收益率也可能不可计算，影响还会进一步延长。

所以你最终研究的不是：

> 这只股票所有交易日的下一日收益率。

而更接近：

> 近期连续有有效行情，并且目标日事后也有完整行情的日期上的下一日收益率。

尤其 `valid[target_pos]` 使用了目标日事后才能知道的完整行情状态。

这不是把未来收益率直接喂给模型，但会形成**事后样本筛选偏差**：

- 实盘可能已经在早上发出预测；
- 当天后来没有有效行情；
- 回测却直接删除了这个预测日。

建议分开记录：

1. `prediction_eligible`：预测时刻能否生成输入；
2. `label_available`：事后是否能计算标签；
3. `tradable_at_decision`：预测时刻是否已知可交易。

评估时报告未获标签、停牌、不可交易的数量及处理方式。

另外你没有抽取股票 `volume`，也没有交易状态字段，所以只靠 OHLC 无法稳妥识别“平价零量”的停牌记录。应补充 `volume`、成交额或交易状态，但也不要把所有零收益率日直接判为停牌。

## 九、切分逻辑：基本正确，不需要机械隔离 60 天

你的切分以：

```python
target_date
```

为准，这比按输入末日划分更清晰。

### 9.1 验证窗口包含训练期历史，不是泄露

例如验证期第一天的输入包含训练期最后 60 天，这完全符合实盘可获得的信息。

同理，在逐日滚动预测中：

- 第二个测试日可以使用第一个测试日已经发生的真实收益率；
- 前提是模型没有用未来测试标签训练，且预处理保持冻结。

这与“在测试期开始时一次性预测整个测试期”是不同任务。你的代码实现的是**逐日滚动的一步预测**。

项目 `Dataset_Custom` 也会给验证、测试区间保留前面的历史窗口。[4]

### 9.2 不需要因为窗口重叠就强制留 60 天空白

你是一步标签、严格按时间顺序切分。窗口共享历史并不自动构成泄露。

更需要防止：

- 随机分配滑动窗口到 train/val/test；
- 训练标签延伸到验证预测时刻之后；
- 验证和测试信息参与特征筛选；
- 反复根据测试成绩改模型。

如果以后扩展到多日标签，再按标签覆盖区间考虑 purge/embargo，而不是机械按 `seq_len` 隔离。

### 9.3 原项目每轮打印测试结果，建议修改

原训练函数每个 epoch 都会计算并打印 test loss，虽然 early stopping 使用的是验证集损失。[2]

这不是测试标签参与梯度训练，但容易让你通过观察测试表现调整模型，污染测试集。

建议：

- 每轮只评估验证集；
- 固定全部选择后再评估测试集；
- 时间允许时采用多个顺序滚动验证区间。

训练集内部 `shuffle=True` 本身没有问题，因为每个样本的时间窗口是完整的；不能打乱的是窗口内部顺序和数据集归属。

## 十、特征与目标口径：能训练，不代表最合适

### 10.1 后复权价格收益率需要确认业务定义

当前目标是：

> 后复权收盘价序列的相邻收益率。

它不应未经核验就等同于：

- 行情软件显示的原始价格涨跌幅；
- 严格定义的含分红总收益率；
- 实际交易可获得收益率。

应选取分红、送转、配股等事件附近的日期，核对数据商复权公式。

同时，不能简单说“后复权一定泄露”：

- 若历史变化只是共同乘上一个常数，相邻收益率会抵消；
- 非统一修订、公司行动处理和财务历史回算则需要具体检查。

### 10.2 原始价格和宏观点位不够平稳

你保留了：

```text
px_open / close / high / low
macro_close
```

这些特征不一定泄露，但可能有长期趋势和区间漂移。

建议优先比较：

- 股价相对昨收、均线的比例；
- 宏观日收益率、多日累计收益率；
- 滚动波动率；
- 成交量相对历史均量；
- 缺失与数据年龄特征。

不是必须删除所有价格水平，而是应做消融实验，确认它们是否提供稳定增益。

### 10.3 两融字段统一除以 100，需要源数据证明

```python
... / 100.0
```

只有原始单位是百分数时才正确。

例如：

- 原值 `3.5` 表示 3.5%，除 100 正确；
- 原值 `0.035` 已经是比例，再除就错；
- 含 `%` 的字符串可能被 `to_numeric(errors="coerce")` 直接变成缺失。

固定缩放在后续标准化中可能被抵消，但这不代表字段语义可以不核验。建议增加解析失败数量、单位、分位数报告。

### 10.4 250 个训练样本只是运行门槛

它不是 TimeXer 泛化能力足够的证明。

项目默认模型维度是 `d_model=512`、`d_ff=2048`，对于单股日频、小样本、较多外生变量，过拟合风险很高。[5]

建议先比较：

- 零收益率预测；
- 训练期均值预测；
- Ridge；
- 小型树模型；
- 小型 TimeXer。

例如从 `d_model=32/64`、1～2 层、较少宏观品种开始，而不是直接使用默认大模型。

### 10.5 `use_norm=1` 不等于泄露，但会改变特征语义

TimeXer 的内部标准化只使用当前输入窗口，并在输出阶段对目标做反标准化，不使用未来标签。[1]

所以：

- 外部训练集标准化；
- 内部窗口标准化；

可以同时存在，并不自动构成错误。

但内部归一化也会作用于缺失标记、年龄、比例特征，改变这些特征的表达。建议把 `use_norm=0/1` 作为验证集上的对照，而不是一律关闭或开启。

## 十一、推理一致性和工程问题

### 11.1 推理未冻结完整日历配置

`infer` 冻结了 `config`，但仍从命令行重新读取：

```text
--calendar
--calendar-start
--min-market-symbols
```

这些会影响：

- 时间网格；
- 历史滚动计算；
- 下一交易日；
- 样本窗口有效性。

应保存并验证历史日历一致性，同时允许追加合法的未来交易日。

### 11.2 `as_of` 是行情日期，不是实际信息截止时刻

当前没有检查：

- 导出是否真的发生在目标日 08:30；
- 所有来源是否已完成更新；
- 最新日线是否已经收盘；
- 数据是否达到可用完整度。

例如周五收盘就运行，脚本生成的是“周一 08:30”的窗口，但周末及周一早上的信息还没有到齐。

建议增加明确的：

```text
forecast_time
source_watermark
snapshot_created_at
```

历史模拟用 PIT 规则回放；实时预测则在指定截止时刻按实际到达的数据生成。

### 11.3 当前股票名单会影响历史回测代表性

用当前行业、市值排名选历史股票，会引入：

- 存续偏差；
- 当前市值筛选偏差；
- 行业变更偏差。

“只用于选股，不当作特征”不能消除这些问题。

不过需要区分：

- **今天指定一只股票，研究今后的预测**：可以这样做；
- **宣称历史上按行业市值前十策略有效**：必须使用历史当时的股票池和排名。

### 11.4 多只股票输出不能直接混成一个模型

各股票独立筛选特征、拟合参数，可能导致：

- 特征数量不同；
- 列顺序不同；
- 标准化含义不同。

每股一个模型没问题；如果以后做联合模型，需要先统一特征 schema 和缩放策略。

### 11.5 代码中展示的特殊方法名需确认

如果实际文件里也是：

```python
def **init**(...)
if **name** == "__main__":
```

那会直接语法错误。应为：

```python
def __init__(...)
def __len__(...)
def __getitem__(...)
if __name__ == "__main__":
```

如果只是粘贴格式变化，可以忽略。

## 十二、建议补上的验收测试

在大规模训练前，我建议至少做以下几类测试。

### 12.1 样本索引与标签一致性

对**全部样本**验证：

```python
assert row.target_pos == row.end_pos + 1
assert row.end_pos - row.start_pos + 1 == seq_len
assert dates[row.target_pos] > dates[row.end_pos]

np.testing.assert_allclose(
    matrix[row.target_pos, -1],
    row.y_scaled,
    rtol=1e-5,
    atol=1e-6,
)
```

再随机抽样，从原始相邻后复权收盘价重新计算 `y_raw`。

### 12.2 未来扰动不影响过去预测输入

固定预测截止时刻 \(D\) 和预处理参数：

1. 生成该时刻的输入窗口；
2. 任意修改 \(D\) 之后才可用的数据；
3. 重新生成同一输入窗口；
4. 两个窗口应完全一致。

这个测试要使用明确的截止时间，不能简单删除日期 \(t\) 之后所有辅助记录，因为周末或目标日早上已经可获得的信息可能合法。

### 12.3 验证、测试数据不影响预处理

修改验证和测试期数值后重新拟合，以下应保持不变：

- 保留特征列；
- 中位数；
- 均值；
- 标准差。

### 12.4 历史数据修订测试

模拟数据库把某条过去记录替换成后来修订值。

如果设计声称历史快照冻结，旧预测窗口就不应该变化。当前实现很可能无法满足，需要 PIT 版本库或持久化快照。

### 12.5 日历缺口测试

人为删除某个真实交易日的大部分行情：

- 系统应报警或保留缺失行；
- 不应把该日期自动当成休市；
- 不应产生跨日跨度错误的单日收益率。

### 12.6 模型输出和反标准化测试

```python
assert pred.shape == y.shape == (batch_size, 1, 1)
```

若使用简单收益率：

```python
return_raw = pred * scale + mean
```

若使用对数收益率，这样得到的仍是**对数收益率**；要转换为简单收益率：

```python
simple_return = np.expm1(log_return)
```

评估应优先使用原始收益率空间的 MAE、RMSE、方向表现和相对基准增益。收益率频繁接近零，不适合把 MAPE/MSPE 当核心指标；单股票跨时间相关性也不要混称为截面 IC。

## 十三、最终目标还有一个关键区分：预测收益率与交易收益不是一回事

你在 \(t+1\) 日 08:30 预测：

\[
C_{t+1}/C_t-1
\]

这可以作为统计预测目标，但此时已经不能按昨天收盘价 \(C_t\) 建仓。

因此：

> 昨收到今收的收益率，不能直接作为今早才产生信号的可实现策略收益。

如果后续要做交易回测，需要明确：

- 是已有持仓的风险或收益预测；
- 还是今早新产生的买入信号；
- 实际成交价格是什么；
- A 股 T+1、涨跌停、停牌及成本如何处理。

不一定要现在修改预测标签，但应避免把这个模型的预测成绩直接转换成“昨收买入、今收卖出”的回测收益。

## 最终建议

**你的脚本值得继续完善，不需要推倒重写。**我建议按以下顺序处理：

1. **先打通接口**：独立股票训练循环，固定 `MS`、`pred_len=1`。
2. **修复 patch 配置**：避免 `60/16` 遗漏最近目标历史。
3. **明确数据可用时间**：逐来源核验发布时间、时区、修订方式。
4. **修复日历逻辑**：数据缺失不能被推断为休市。
5. **真正冻结历史快照**：版本化原始数据或追加式特征存储。
6. **区分可预测、可标注、可交易日期**，报告被删除样本。
7. **先跑简单基准，再上小型 TimeXer**，测试集不参与调参。

**一句话判断：标签和切分主干是对的；真正影响可信度的，是原项目接口不匹配、默认 patch 截断、数据源的历史可用性、日历校准和历史快照重建，而不是有没有使用 `shift(-1)` 或 `bfill`。**
